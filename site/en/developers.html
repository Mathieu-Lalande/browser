The code is readable on GitHub: architecture, decisions, tests. Found a bug or have an idea? Open an issue or a merge request: every contribution is reviewed by the maintainer.

View the code Issues Merge requests

Architecture

  • Desktop: Electron 44 (main process in TypeScript), UI in Svelte 5 (runes), built with electron-vite.
  • Phone: Expo / React Native in mobile/, sharing the src/shared core without copying it.
  • Shared core: src/shared stays pure (no Electron, Node or DOM) and unit-tested: models, validation, sync engine, i18n.
  • Sync: a self-hostable relay in server/, which never sees plain data (end-to-end encryption).
  • Security: web pages get no preload and no Node access; every IPC message is declared in src/shared/ipc.ts and its arguments are checked in main.
  • Decisions: every structural choice is an ADR in docs/DECISIONS.md.

Get started

Node 22 and Git are enough; Electron's binary is downloaded on install.

git clone https://github.com/Mathieu-Lalande/browser.git
cd browser
npm install
npm run dev

Local installers: npm run dist:dir. Per-system details in docs/INSTALL.md.

Check before proposing

The same chain runs in continuous integration on every merge request:

npm run typecheck      # TypeScript + svelte-check, no warning
npm run check:cycles   # no import cycle in the main process
npm run check:i18n     # no hard-coded UI text
npm test               # unit tests (Vitest)
npm run build
npx playwright test    # end-to-end tests in the real app

Depending on what you touch: cd mobile && npx tsc --noEmit && npx jest, npm run test:server, cd site && npm run build.

Open a merge request

  1. Open an issue first for a large change: we agree on the approach before the code.
  2. Create a dedicated branch from master and keep the change focused.
  3. Follow the conventions: code and comments in English; every UI text in both catalogs fr.ts and en.ts; Lucide icons; spacing through the global.css tokens.
  4. Nothing written to disk from a private window; no data sent without a user action.
  5. Add tests: unit tests for pure logic, Playwright for visible behavior.
  6. Describe in the request what changes, the tests you ran and the limits left per system.

The full guide is in CONTRIBUTING.md. Browser is proprietary software (license): an accepted contribution is merged by the maintainer.

Report a vulnerability

Never in a public issue: use GitHub's private security advisories, as explained in SECURITY.md.
